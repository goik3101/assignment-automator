## 겹침방지 (DB에 쓰지 않고 점검)

- **테스트는 실제 서비스의 겹침방지에 영향을 주지 않는다**: 측정 스크립트는 서버 경로(`identifyCluster`·`saveResultEmbedding`·`recordRecommendation`)를 타지 않는다.
  점검 전후로 실제 표 행 수를 셌다 — `clusters` 83→83, `task_embeddings` 670→670, `cluster_match_logs` 679→679, `recommendation_history` 447→447(전부 불변).
  (`user_histories`는 444→438로 줄었으나 우리 스크립트는 그 표를 읽지도 쓰지도 않는다 — 실사용자의 삭제로 보인다.) 전에 쓰던 전역 삭제는 하지 않았다.
- 읽기 전용 `match_cluster`로 34종 분석을 매칭해 봤다: 전부 "매칭 없음" → 이 테스트 안내문은 실제 클러스터에 섞이지 않았다. 자가 점검(실제 클러스터 샘플을 다시 임베딩)에서 자기 자신이 sim 1.000으로 잡혀 **RPC는 정상**이다.
- 자동 선정(메모리 이력으로 학생 4명 연속): 사회-02 서로 다른 대상 4/4, 역사-03 4명 중 2건이 같은 유물을 다시 고름(1번이 "대향로+정림사지" 조합이라 부분 겹침), 과학-08 서로 다른 3(+대상 없음 1).
  선정 점수가 소프트맥스라 이력이 4건뿐이면 겹침이 남는다 — 설계 그대로이고 이력이 쌓이면 억제가 세진다.
- 결과물 의미 유사도(코사인): 같은 안내문 학생끼리 0.63(역사-03)·0.77(역사-04)·0.81(사회-02)·0.90(과학-08). 쏠림 문턱 0.85를 같은 안내문이 넘는 일이 흔하다 —
  비율 계산이 `(유사+1)/(전체+25)`라 건수가 적을 땐 발동하지 않는다(설계). **STRONG 회피 지시의 효과는 표본 3명씩으로 0.772 → 0.747**(차이가 흔들림 안)이라 효과를 못 박지 못한다.

## 추가 (같은 날 오후 — 사용자 실사용 피드백)

- **요약이 이상한 낱말만 알려 준다**(과학 멸치): 용어 칸에 "관찰 지침"·"예상과 실제 관찰"·"영양단계의 연결"이 올라오고 생산자·소비자·분해자는 없었다. 원인은 11-13에 넣은
  "교과서 수준 상식은 넣지 말 것"(`termInstruction`)이었다. 요약에서는 그 지시를 빼고 **교과 개념 + 교과서 기준 정확한 뜻**을 쓰게 했으며, 코드가 ① 자료에 없는 합성어 ② 과제 진행·문서 구조 말을 거른다(`study/summary-terms.ts`).
  재실행 2회: 생산자·소비자·1차 소비자·분해자·먹이그물·생태계 평형(전부 정확). 칸이 여럿이면 요점은 칸마다 1~2문장으로 나눈다.
- **요약이 저장 안 된다**: 브라우저 저장 키가 "방금 만든 화면"에서는 `submission:<id>`, 기록 화면에서는 `history:<id>`라 서로 못 찾았다 → 둘 다 `work:<submission_id>` 한 키를 쓰고 예전 키도 읽는다(`useStudyData.ts`). **서버(계정)에 저장하는 것은 아니다** — 다른 기기·브라우저 데이터 삭제 후에는 다시 만든다. 계정 저장은 DB 표가 필요해 승인 먼저.
