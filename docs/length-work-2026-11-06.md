# 글 분량 맞추기 작업 기록 (2026-11-05 ~ 11-07)

원래 채팅에서 이어 하기 위한 인계 문서. **커밋하지 않았다.** 새 코드는 전부 환경변수 스위치 뒤에 있고 **기본 꺼짐**이다
(`.env.local`·`.env`에 스위치 없음 확인) — 스위치를 켜지 않으면 프롬프트·출력이 달라지지 않는다.

## 1. 처음 문제

- 수행평가 글이 어떤 때는 **길어야 하는데 짧게**, 어떤 때는 **2~3줄이면 될 칸에 5줄 이상**으로 나온다.
- 안내문에 분량(몇 줄 등)이 없을 때를 잡을 기준이 필요하다. ChatGPT(무료)는 같은 모델인데도 대체로 맞춘다.
- 조건: 글 품질·출처 품질은 건드리지 않는다. 생성 테스트 횟수는 사용자가 정한다.

## 2. 진단 (코드 읽기·비용 0)

- `essay/length-plan.ts`: 분량이 없으면 **단계 이름의 낱말**로 역할(소감·보고서·계획…)을 정해 고정 글자 범위를 프롬프트에 박는다.
  낱말에 안 걸리면 `general`(500~1,100자)로 떨어진다.
- 분량 보정(생성 뒤 글자 수 맞추기)은 시간 예산(22초)에 밀려 **56회 중 0회** 돌았다(PROGRESS.md "분량 준수" 항목) → 분량은 프롬프트로 처음부터 맞춰야 한다.
- 찾은 구멍 ① **"약 5줄"·"3줄 분량"·"5줄로 작성"을 줄 수 조건으로 못 읽었다**(`form-requirements.ts`는 "5줄 정도·이내·이상·2~3줄"만 읽음).
  신문 안내문에 "내용 약 5줄"이 분명히 있는데 머리기사에 900~1,500자 기본 범위가 붙었다. 분석 프롬프트(`analyze.ts`)는 이미
  "양식 칸 분량: '<칸 이름>' 약 N줄"을 쓰게 하고 있었으니 읽는 쪽만 빠진 것.
- 구멍 ② **"A4 1장 이내·원고지 5매·1~2쪽·한 페이지·반 쪽"이 22개 표현 중 한 개도 안 읽혔다**(길이 파서는 자·단어·분만 봄).
- 구멍 ③ 제목·이름 기입란(책 제목, 카드뉴스 제목)이 안내문에 줄 수가 없으면 설명 문장이 붙어 4~5문장으로 나왔다.

## 3. 만든 것 (스위치, 전부 기본 꺼짐)

| 스위치 | 내용 | 파일 |
|---|---|---|
| `LINE_LENGTH=on` | ① "약 N줄·N줄 분량·N줄로"를 줄 수 조건으로 읽기(문단·문장은 일부러 안 넣음 — 항목별 지시를 단계 총량으로 오인해 거짓 보완을 부름) ② 형식 조건에 "한 줄≈공백 포함 30자(25~35)" 환산 문구 ③ 제목·이름 기입란 한 줄 규칙 ④ 쪽·장·매 → 글자 수 환산 가이드 | `essay/form-requirements.ts`, `essay/page-length.ts`(신규), `essay/length-plan.ts`, `gemini/generate-essay.ts` |
| `LENGTH_INFER=on` | 분량 없을 때 서술형 300~500 / 의견 500~800 / 주장 800~1,200 / 탐구 1,200~2,000 / 심층 2,000~2,800자로 유형 추론(분량 기준 문서 3순위) | `essay/length-plan.ts` |

- 쪽 환산: A4 한 쪽≈1,000자, 원고지 한 매=200자. "이내"는 0.6~1.0배, "이상"은 1.0~1.3배, 그 밖은 0.8~1.1배.
  **경고·재시도 경로(`target_length`)에는 넣지 않고 프롬프트 가이드로만** 쓴다(환산이 추정이라 거짓 "분량 미달" 경고 방지).
  "카드뉴스 6장"·"3쪽 이상의 자료를 찾아"·"12쪽 책을 읽고"는 읽지 않는다.
- 테스트: `page-length.test.ts`(신규), `form-requirements.test.ts`에 추가. `node --test src/lib/essay/*.test.ts` 302개 통과,
  `rule-audit` 놓침 0·오발동 0, `prompt-audit` 블록 충돌 0, `tsc` 소스 오류 없음.
- `scripts/measure/final-check.ts`: 결과 파일 이름 접미사(`FC_TAG`), 단계별 글자 수 출력, 쪽·매 검증용 사례 2개(`사회 평가지(A4 1장)`, `화작(원고지 8매)`) 추가.
- 분량 기준 문서: `수행평가 안내문/줄chatgpt기준.txt`(우선순위: 명시 분량 → 양식 칸 → 과제 유형 → 평가 기준 → 일반 관행).

## 4. 실험과 결과 (전부 n=1, 같은 안내문도 분석이 매번 달라 비교가 거칠다)

1. **분량 가이드 제거(`LENGTH_GUIDE=off`) — 기각·되돌림.** 안내문 3종 각 1회: 카드뉴스 1,273→796자, 신문 1,838→1,257자.
   당시엔 "더 짧아져 나쁘다"고 읽었으나, 내용으로 보면 카드뉴스는 끈 쪽이 칸에 더 맞았다. **글자 수만 보고 판단한 것이 오판이었다**
   (신문 만평 "17자"는 비어서가 아니라 설명 문단이 "제작 참고" 뒤로 밀린 것). 켬/끔 어느 쪽이 낫다고 결론낼 수 없다.
2. **평가 기준 개수로 상한 줄이기 — 기각(코드에서 뺌).** 기준을 문장 매칭으로 세면 부정확해 8장면 스토리보드가 "500~500자"가 됐다.
3. **줄 수 읽기(신문)**: 머리기사 650→303자, 인터뷰 464→286, 사설 443→213. 사설은 5문장으로 5줄 칸 크기에 맞음. 이 실행에서 만평/광고 단계가 빠졌는데 분석 변동으로 보이나 이번 수정과 무관하다고 확인하진 못함.
4. **분량 지시 없는 4종 점검**(카드뉴스·과학·화작·사회): 스위치가 바꾼 게 없음(효과 미확인). 대신 기본 동작의 결함이 보임 —
   카드뉴스 기입란이 4~5문장·카드 ①↔③ 반복, 화작 글머리에 안내문 문구 유입("현안을 담은 기사에서 사회문제를 찾고:"),
   과학 출처에 PDF·다운로드 링크·초등 5학년 자료, 사회 되풀이 3건.
5. **제목 칸 규칙(카드뉴스)**: 책 제목이 4문장 소개 → `『사일구』 윤태호 [1]` 한 줄, 전체 1,758→669자. 출처 3개 전부 공식 자료. 단 "내용" 칸에 근거 없는 인물명("현용") 1건.
6. **쪽·매 읽기**: 사회 평가지 + "평가지는 A4 1장 이내" → 평가지 1,347→1,006자(목표 600~1,000), 7개 항목 유지. 화작 + "원고지 8매 내외" → 1,145→1,855자(목표 1,280~1,760, 5% 초과).

## 5. 열린 문제 (중요도 순)

- **자기 활동 날조 검사 구멍**: 6번 화작 결과에 "나는 지역 청년센터에서 열린 강연을 듣고…, 강연자는 현장 사회복지사"가 지어져 들어갔는데 결함 검사기는 날조 0건으로 셌다.
  길이를 늘려서 생겼는지, 분석이 "강연·대화" 항목을 새로 만들어서 생겼는지는 못 가렸다. **길이를 늘리는 방향은 이 구멍부터 막아야 안전하다.**
- 사회 평가지 칸 이름 접두어("주제와 선정 이유 또는 동기:")가 두 칸에 중복. 화작 글머리에도 같은 현상(안내문 문구 유입).
- 카드뉴스 반복(①↔③)을 반복 검사기가 못 잡는다: Dice 유사도 0.56 < 기준 0.72인데, 기준을 낮추면 과학 안전 수칙(0.58) 같은 정당한 반복이 같이 잡혀 오탐이 늘어난다 → 기준값 조정은 안 맞고 의미 비교가 필요(모델 호출 비용).
- 앞 단계에 없는 출처 사용(국어 스토리보드 [3]): 검사는 작동하지만 보완이 시간 예산(28~38초)에 밀려 건너뜀. 실제 피해는 작다고 판단해 그대로 둠(예외 적용은 +5~8초).
- 과학 출처 품질(PDF·다운로드·초등 자료), 안내문 분석이 매번 달라지는 문제(단계 수·항목 구성 변동).
- 미검증: `LENGTH_INFER`(해당하는 안내문이 없었음), 한 줄 30자 환산(실제 평가지 칸 확인 못 함), 예시 답안 분량 따르기.

## 6. 테스트 예산 사용

- 사용자 지정 "총 5번": 신문 1 + 분량 없는 4종 4 = 5회, 이후 1회 추가 승인(카드뉴스) = 6회.
- 사용자 지정 "기준 하나당 2회, 총 10번 이내": 쪽·매 읽기에 2회 사용 → **8회 남음.**
- 그 전에 가이드 켬/끔 비교로 약 4회(3종 + 중단)를 썼다. 1회 약 0.03~0.07달러.

## 7. 다음에 할 일 (제안)

1. 자기 활동 날조 검사 구멍을 비용 0으로 먼저 고친다(저장된 결과물로 재현 가능: `fc-화작(원고지 8매)_pg.md`).
2. 그다음 남은 기준 후보(예시 답안 분량 따르기, 유형 기본값)를 오프라인으로 거르고 기준당 2회로 검증한다.
3. 결과가 괜찮으면 `LINE_LENGTH`만 기본 켜짐으로 바꾸는 것을 검토한다(원인이 명확한 읽기 오류 수정이라 위험이 가장 작음).

## 8. 재현 명령

```bash

```

결과물: `scratchpad/measure/out/fc-<사례>_<태그>.md`, 로그 `lg-*.log`.
