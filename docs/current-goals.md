# 현재 작업 목표와 사용자 지시 원문

세션이 압축되어도 목표가 어긋나지 않도록, 사용자가 직접 붙여넣은 지시와 번호 목록을 원문 그대로 보관한다.
번호로 지시받았을 때(예: "2번 진행해줘")는 아래 어느 목록의 몇 번인지 모호하면 먼저 확인할 것.
작업 규칙 요약은 `CLAUDE.md`의 "현재 작업 목표와 작업 규칙" 참고. 진행 기록은 `PROGRESS.md`.

## A. 남은 문제 목록 (2026-10-19, 사용자 붙여넣기)

> 남은 문제
>
> 1. 책 과제는 50~70초: 책 선정(약 15초)과 저자 확인(약 10초)이 따로 있고 아직 조사/글쓰기 구조도 아니에요. 다음 순서로 가장 효과가 클 거예요.
> 2. 선정형 과제(인물 고르기): 조건 분석 4~8초 + 후보 생성 12초가 앞에 붙어요. 분석 단계로 옮기면 신문이 30초 안으로 들어올 수 있어요.
> 3. 글+계획 혼합 과제: 계획 쪽의 통계 검증 호출이 최대 46초(`verifyExcerpt` 3번)까지 걸려요.
> 4. 분량 보정: 글쓰기가 가끔 목표를 20~60% 넘겨서 6~15초가 더 들어요(마지막 5번 중 1번).
> 5. 아직 검증하지 못한 것: 조사 실패 시 예전 경로로 돌아가는 폴백(자연스럽게 발생하지 않아서 실제로는 못 봤어요), 영어 과제, 우선 처리 등급이 실제 계정 한도에서 안정적으로 유지되는지.

(사용자 설명: 1번은 이미 완료. 2번은 선정형 과제 속도 — 시도했으나 호출 합치기·동시 실행 모두 효과 없어 되돌림. 4번은 분량 보정 — 목표 분량 계수 조정 실험이 효과 없어 되돌림.)

## B. 최종 목표와 5개 요구 (2026-10-19, 사용자 붙여넣기)

> 우리 최종 목표는 인물 선정 단계만 줄이는 게 아니라, STUDED 전체 과제 생성 시간을 30초 이내로 줄이면서 글 품질과 출처 정확도를 유지하는 것이야.
>
> 1. 이전 테스트에서 신문 과제가 32~39초였는데 이번에는 54~58초인 이유부터 분석해. 테스트 조건, 코드 경로, 캐시, 재작성 횟수를 비교해.
> 2. 전체 파이프라인에서 시간이 오래 걸리는 부분을 다시 측정하고 병목을 우선순위화해.
> 3. 작은 호출에 빠르고 저렴한 모델을 사용하는 방안을 검토하되, 기존 모델과 속도·비용·한국어 표기·후보 정확도·출처 정확도를 비교해.
> 4. 효과가 검증된 변경만 적용하고, 실패하면 기존 방식으로 돌아갈 수 있게 해.
> 5. 변경 전후 실제 측정 결과를 보고해. 효과가 없으면 억지로 수정하지 마.
>
> 특정 단계의 속도만 줄이는 데 그치지 말고 전체 생성 시간을 기준으로 판단해. 기존에 개선한 조사 노트 재사용과 출처 검증 기능도 유지해.

## C. 자율 판단 지시 (2026-10-19, 사용자 붙여넣기)

> 지금까지의 대화와 코드 변경 내역을 검토하고, STUDED의 원래 목표에 맞게 다음 작업을 스스로 판단해 줘.
> 최종 목표
>
> * 과제 생성 시간을 30초 이내로 줄이기
> * 글의 품질, 출처 정확도, 학생별 결과물의 다양성 유지
> * 불필요한 API 호출과 비용 낭비 방지
> * 기존 기능과 안정성 유지
>
> 네가 판단할 것
>
> 1. 조사 노트 재사용 캐시가 원래 목표에 부합하는지, 유지·수정·비활성화·롤백 중 무엇이 적절한지 판단해.
> 2. 최근 최적화 실험에서 실제 효과가 있었던 변경과 없었던 변경을 구분해.
> 3. API 비용이 예상보다 많이 발생한 원인을 로그와 사용량 근거로 조사해.
> 4. 전체 생성 파이프라인에서 가장 효과가 큰 다음 최적화 작업을 선정해.
>
> 먼저 코드와 커밋을 확인하고, 효과와 위험을 비교해서 네가 최선이라고 판단하는 방향을 제안해 줘.
> 단, 캐시 데이터 삭제, 대규모 구조 변경, 추가 비용이 발생하는 대량 테스트는 내 승인 없이 하지 마. 확인된 문제를 근거로 판단하고, 추측을 사실처럼 말하지 마. 아직은 코드 수정 전에 최종 계획과 판단 근거를 보고해 줘.

## 진행 상태 (2026-10-19)

- 적용됨(효과 확인): 조사→글쓰기 분리 + 우선 처리 등급, 책 과제 빠른 경로.
- 조사 노트 재사용 캐시: 코드는 있으나 **기본 꺼짐**(`RESEARCH_CACHE=on`일 때만). 이유 — 같은 과제를 독립 실행하면 출처 URL이 겹치지 않는데(0%) 캐시는 모든 학생에게 같은 사실·출처를 주어 다양성을 해친다. 마이그레이션 0017은 적용하지 않는다.
- 기각(되돌림): 조건분석+후보생성 합치기, 둘 동시 실행, 작은 모델 교체(후보/조사/글쓰기), 조사 사실 개수 축소, 글쓰기 목표 분량 계수 0.65.
- 남은 병목: 분량 보정 호출(+5~8초, 실측 25건 중 5건), 조사 실패 후 기존 경로(+15~25초, 진단 로그 추가됨), 이상문자/저자 검증 재시도, 인물 자동 선정 11~13초.
