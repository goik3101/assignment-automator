# 생성 파이프라인 규칙 상세 (원문 보관)

CLAUDE.md에서 덜어 낸 **날짜별 실측 기록과 근거 전문**이다(2026-11-19에 옮김, 내용은 글자 그대로).
CLAUDE.md에는 규칙·스위치만 남아 있다. **에세이 생성·안내문 분석·측정 코드를 건드릴 때는 통째로 읽지 말고 관련 항목을 검색해서 읽을 것**
(예: `grep -n "분량" docs/essay-pipeline-notes.md`). 새 실측 기록은 여기에 더한다.

## A. essay/ 파일 지도 (폴더 구조에서 옮김)

```
    essay/                        -- 완성 원고 품질 규칙(순수 함수, alias import 없음): deliverable(신문 등 산출물 형식·참고목록/작업설명 제거),
                                     length-plan(단계 역할별 분량 가이드), form-rules(글 종류별 작성 방식), source-select(출처 2~3개로 정리),
                                     claim-check(문장↔출처 페이지 대조), coverage·repetition(누락·반복 검사), excerpt-need(원문 구절 요구 여부), research-notes(조사→글쓰기 사실 노트), research-cache(+key: 같은 수행평가 학생끼리 조사 노트 재사용, 마이그레이션 0017),
                                     quality-flags(품질 개선 스위치 ESSAY_QUALITY_FIXES=off로 되돌림), prompt-scope(과제에 해당할 때만 공통 규칙 블록 포함), opinion-citations(감상 문장 각주 제거),
                                     form-requirements·form-repair(안내문의 개수 조건 — 8장면·N문장·N문단 — 을 프롬프트에 전하고 생성 뒤 코드로 세어 어긴 단계만 한 번 보완. FORM_REQUIREMENTS=off로 되돌림),
                                     evidence-slots(안내문이 요구한 "서로 다른 근거 N개"와 학생 입장을 조사에 전하고, 근거가 한 페이지에 몰리면 1회 보강),
                                     step-order(안내문이 "A를 바탕으로 B"라고 한 단계만 순차 생성 — 기본 꺼짐), plan-citations(쓸 순서를 말하는 계획 문장의 각주 제거),
                                     own-activity(촬영·스크랩처럼 학생이 하지 않은 행동을 "했다"고 쓴 문장 탐지 + "[직접 작성]" 빈칸 과다 검사),
                                     data-visual(안내문이 요구한 표·그래프를 실제로 만들었는지 + 안내문이 금지한 자료(사진·영상)를 썼는지),
                                     uncited-figures(각주 없는 수치 문장을 찾아 노트에 있는 값은 코드가 출처를 붙이고, 노트에 없는 값은 그 단계만 다시 쓰게 함),
                                     form-requirements의 wantsBriefScenes(안내문이 "스토리보드에는 간단히 표시"·"대본 없이"라고 하면 장면의 말할 내용을 완성 대본이 아니라 핵심 낱말 한 줄로),
                                     time-range(안내문이 "1945.8.15.~1948.8.15."처럼 다룰 기간을 못 박은 과제에서만 발동 — 그 시점에서 쓰는 글이므로 범위 밖 연도를 코드로 센다),
                                     source-voice(근거가 "그 문서가 무슨 말을 했나"로 쓰였는지 — 낱말 목록이 아니라 **그 글의 출처 제목**과 문장 주어를 맞춰 보므로 과제 유형과 무관하다. 근거 항목 안에서만 돌고, 기관이 실제로 한 일과 책 제목은 건드리지 않는다),
                                     compound-items(항목 이름이 "글의 목적·주제·예상 독자"처럼 여러 가지를 나열하면 한 문단에 뭉치지 말고 줄을 나눠 각각 쓰게 함 — 이름이 나열형일 때만 발동하고 "산과 염기의 특징"처럼 끝말이 다른 "과/와"는 쪼개지 않는다),
                                     step-order의 extraCitations(앞 단계를 바탕으로 쓰는 단계가 앞 단계에 없는 출처를 들고 왔는지 번호로 검사 — 프롬프트 지시만으로는 막히지 않는다),
                                     refusal(제출할 글에 섞인 "자료가 없어 못 쓰겠다·보내 주면 정리해 드리겠다" 같은 거절문을 찾아 그 단계만 다시 쓰게 함 — 날조 차단의 반작용),
                                     ascii-art(기호로 그린 그림을 제출할 글에서 뺀다 — 학생이 준비할 사진 자리를 코드 블록이 대신 차지했다. 글자가 대부분인 블록은 두고 기호 비율로만 가른다),
                                     english-grammar의 missingUnderlinedForms(안내문이 "그 표현에 밑줄"을 요구하면 어법을 썼는지뿐 아니라 **밑줄까지 쳤는지** 센다 — 굵게로 나가면 그 항목이 0점이다)
```

## B. 작업 규칙 전문

(아래는 옮기기 전 CLAUDE.md의 "현재 작업 목표와 작업 규칙" 구역 전문)

- **다른 세션에서 이어받으면 `PROGRESS.md`의 첫 장 "지금 상황과 다음에 할 것"부터 읽을 것** —
  지금 점수판, 최근에 한 것, 다음에 할 것(파일·함수·측정 명령까지), 자주 밟는 함정이 거기 모여 있다. 날짜별 상세는 같은 파일 맨 아래로 쌓인다.
- **최종 목표:** 과제 생성 시간 30초 이내 + 글 품질·출처 정확도·학생별 결과물 다양성 유지 + 불필요한 API 호출/비용 방지 + 기존 기능·API 응답 형식 유지. 한 단계가 아니라 **전체 생성 시간**으로 판단한다. 사용자가 붙여넣은 지시·번호 목록 원문과 진행 상태는 `docs/current-goals.md`에 있다 — "N번 진행해줘"처럼 번호로 지시받으면 어느 목록의 몇 번인지 거기서 확인하고, 모호하면 먼저 묻는다.
- **승인 없이 하지 않는 것:** 캐시 데이터 삭제, 대규모 구조 변경, 추가 비용이 드는 대량 테스트, DB 마이그레이션 추가·적용. "승인 먼저 받겠다"고 말한 작업은 답을 받기 전에 구현하지 않는다.
- **항상 추가만 하지 말 것 — 빼기·가볍게 하기를 먼저 의심할 것**(2026-11-17, 사용자 지시). 문제가 생길 때마다 규칙·프롬프트·보완 호출을 더해 왔는데, 측정해 보니 **생성 뒤 AI가 다시 손보는 층**(조건 대조·선택 보완)은 점수를 못 올리면서 시간과 거짓 경고만 늘렸다(같은 10종: 점수 115→121/131, 시간 합계 267→233초로 줄이자 오히려 나아짐). 코드로 고정된 결정적 후처리는 반대로 점수에 기여했다(전부 끄면 −7점). 그래서 **새 규칙을 더하기 전에 ① 기존 층 중 무겁거나 겹치는 것을 끄는 실험을 먼저 하고 ② 끈 쪽이 같거나 낫다면 지울 것.** 원인을 못 찾는 문제는 "더 막는" 쪽이 아니라 "어느 층이 방해하는가"로 접근한다. 점수판은 글 내용만 재므로 시간·거짓 경고·화면 결함은 `screen-dump`·`screen-lint`·`plan-vs-actual`로 같이 본다.
- **실험 규칙:** 효과가 실측으로 확인된 변경만 적용하고, 실패하면 기존 방식으로 돌아갈 수 있게(환경변수 스위치 등) 하며, 효과가 없으면 억지로 수정하지 않고 되돌린다. 이미 기각한 실험은 `docs/current-goals.md`의 진행 상태에서 확인하고 같은 방식으로 반복하지 않는다. 추측을 사실처럼 말하지 말고 측정값에는 표본 수를 함께 적는다.
- **조사 노트 캐시**(`lib/essay/research-cache*.ts`)는 기본 꺼짐이다(다양성 저하 우려). 켜려면 `RESEARCH_CACHE=on`.
- **품질 개선 스위치**: `ESSAY_QUALITY_FIXES=off`면 2026-10-21~22 점검에서 바꾼 프롬프트·후처리(양식 충실 규칙, writing_guide 사용, 작업 메모·주소 제거 등)를 전부 예전 방식으로 되돌린다. 글쓰기 호출만 다른 모델로 바꾸려면 `OPENAI_MODEL_WRITE`(없으면 `OPENAI_MODEL_MAIN`). 안내문 분석은 `OPENAI_MODEL_ANALYZE`, 공부 도구(요약·플래시카드·퀴즈·가상 시험·암기노트·예상 질문)는 `OPENAI_MODEL_STUDY`(둘 다 없으면 `OPENAI_MODEL_LITE`, 현재 gpt-6-luna). 테스트 스크립트는 `SOURCE_STATS_LOG=off`로 링크 통계(source_validations)에 기록을 남기지 않는다. 속도 스위치(2026-10-23, 기본 켜짐): `ESSAY_PARALLEL_WRITE=off`(단계별 동시 글쓰기 끄기, `lib/essay/parallel-write.ts`), `ESSAY_BOOK_EXCERPT=legacy`(구절 요구 책 과제를 예전 경로로), `ESSAY_AUTHOR_PRECHECK=off`, `PLAN_REUSE_ESSAY_FACTS=off`(계획이 원고 사실을 재사용하지 않고 다시 조사).
- **3차 전체 점검(2026-11-15, `docs/full-check-2026-11-15.md`) — 코드로 강제한 후처리와 스위치**: 안내문 34종을 전수로 돌려 반복되는 모양을 코드가 바로잡게 했다.
  분석 단계 보정 `foldSkeletonItems`(서론·본론·결론 뼈대와 내용 항목이 섞이면 뼈대만 칸으로)·`soloDefault`(학생이 팀을 말하지 않으면 "팀 진행 시" 칸 제외),
  생성 후처리 `essay/extra-material.ts`·`source-list-need.ts`·`prompt-leak.ts`·`item-label.ts`·`bibliographic-fields.ts`·`source-line.ts`·`hanja-scope.ts`와 `deliverable.ts` `placeSourceList`(모델이 쓴 참고문헌을 시스템 출처로 제자리 교체),
  `own-activity.ts` `removeOwnActivitySentences`(`HONESTY_REMOVE=off`; 보완 뒤에도 남은 "사진 준비해 첨부했다" 류를 지움). 되돌리기: `RESEARCH_RETRY=off`(조사 비었을 때 재시도), `PARTIAL_INSUFFICIENT=off`(한 단계만 자료 부족이면 그 단계만 빈칸).
  **`ensureQuestionSteps`의 덮임 판정은 이름·칸의 낱말 60% 겹침이다** — 이름만 보면 과학-09에서 단계를 둘 더 붙여 결과물이 통째로 실패했다(회귀 테스트 `analysis-questions.test.ts`).
  **측정 도구**: 전수 `giant-check.ts`(조사 미리 띄우기를 흉내 내 조사초·생성초·합계초를 따로 적는다)와 `full-table.mjs`, 구조 이상 전수 `structure-audit.ts`, 공부 도구 `study-check.ts`,
  겹침방지는 DB에 쓰지 않는 `diversity-check.ts`·`cluster-readonly-check.ts`(전후 행 수 비교)로 본다 — **측정 때문에 실제 서비스의 겹침방지 표가 바뀌지 않게 서버 경로(`identifyCluster` 등)를 타지 말 것**.
- **글 품질 작업(2026-10-29~30) 스위치** — 전부 기본 켜짐, 괄호 안 값으로 되돌린다. 근거와 측정값은 `PROGRESS.md`의 같은 날짜 항목에 있다.
  `OPENAI_MODEL_WRITE=gpt-6-luna`(완성 원고 글쓰기만 luna — mini 대비 24.8→20.4초·되풀이 1.3→0쌍, 더 비싼 gpt-6-sol·gpt-5.6-luna는 이 과제에서 더 낫지 않았다), `ESSAY_WRITE_EFFORT=low`(luna는 minimal을 거부),
  `ESSAY_WRITER_KNOWLEDGE=strict`(기본은 교과서 수준 일반 지식 허용 — 금지해 두면 노트 10~14개 사실만으로 글을 채우느라 같은 말이 되풀이됐다),
  `UNVERIFIED_MARK=off`(본문에 "[확인 필요]" 표시), `ESSAY_EVIDENCE_SLOTS=off`, `PLAN_CITATIONS=off`, `ESSAY_STEP_ORDER=off`(2026-11-01 기본 켜짐으로 바꿈 — 안내문이 "개요에서 생성한 내용을 바탕으로"를 직접 묻는데 동시 생성이면 뒤 단계가 앞 단계 글을 물리적으로 못 본다. generateEssay 27~34초 유지),
  `ESSAY_MAX_BLANKS`(기본 4 — 기사 스크랩은 제목·날짜·신문사 세 칸이 정당한 빈칸이라 3이면 매번 걸린다), `ESSAY_ITEM_PARALLEL=off`(단계가 하나뿐일 때 항목을 둘로 나눠 동시 쓰기), `ESSAY_TIME_BUDGET_MS`(기본 22000, 0이면 끔 — 넘으면 품질 교정용 추가 호출을 건너뛰되 안내문 요구를 채우는 보완은 +4초까지 허용),
  `SOURCE_LIMIT`(출처 정리 한도, 기본 5 — 예전 3은 각주 49개·출처 32개를 잘라냈다), `SOURCE_JUDGE=on`(작은 모델 판정으로 각주를 옮기던 경로, 기본 꺼짐).
- **30초로 재야 할 것은 `generateEssay` 단독이다**(실측 21~39초). analyze(12~20초)는 별개 요청이고 그 사이에 사람이
  들어간다 — `NewCreationModal`은 analyze → 분석 결과 확인 → 모드 선택 → 제작 전 질문 2~4개 → 그때서야 생성이다.
  그래서 "analyze와 조사를 겹치자"는 **불가능**하다(2026-10-31 철회). 남은 겹치기 후보는 제작 전 질문에 답하는 동안
  조사를 미리 띄우는 것인데, 답이 주제·입장을 바꾸면 엉뚱한 조사를 쓰게 된다.
- **안내문을 제대로 지켰는지는 `scripts/measure/truth.ts`로 잰다** — `rubric-check`의 체크리스트는 analyze가 요약한
  조건에서 나오므로 **analyze가 흘린 조건은 그 감사도 못 본다**("조건 8/8"인데 안내문 위반이 남는다).
  truth.ts는 안내문 사진을 사람이 직접 읽어 적은 정답 체크리스트로 채점한다. 정답을 적을 때 **안내문에 없는 조건을
  지어내지 말 것** — 2026-10-31에 과학 과제에 없는 "표로 정리" 조건을 넣어 멀쩡한 결과물을 4/5로 잘못 깎았다.
  이미 기각한 것: 글 쓰는 호출에 안내문 사진 함께 보내기(국어 8/9→8/9, 과학 11/11→11/11, 틀린 항목까지 동일).
- **(철회됨) 생성 시간의 하한은 ~35초다**(2026-10-31 호출별 실측): analyze 12~20초 + 조사 7~13초 + 글쓰기 12~20초가
  직렬이지만 analyze는 사람이 한 번에 기다리는 시간이 아니다(위 항목). ChatGPT는 호출 1건 + 스트리밍이고 우리는 직렬 3단계 + 스트리밍 없음이라 같은 모델로도 체감이 다르다.
  그래서 `ESSAY_TIME_BUDGET_MS`의 기본 22초는 생성 하한보다 **아래**이고, 그 뒤 품질 보완은 처음부터 거의 못 돈다.
  **시간을 줄이려면 품질을 깎는 게 아니라 직렬 단계를 겹쳐야 한다.** 호출별 분해는
